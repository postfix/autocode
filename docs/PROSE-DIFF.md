# Recovered Ultracode prose versus active Autocode instructions

This compares the Ultracode-specific prompt surfaces identified in the Claude Code 2.1.310 recovery inventory. It does not claim that every generic Claude Code system prompt was recovered. The extracted source prompt files are now shipped in [`references/source-prompts/`](../references/source-prompts/); npm `latest` has not received these candidate changes. "Active" means an instruction is loaded by the skill or sent by an SDK adapter. A preserved file alone is not active.

## Subagent prompts: what an agent actually receives

Both [`codex-adapter.mjs`](../scripts/codex-adapter.mjs) and [`claude-adapter.mjs`](../scripts/claude-adapter.mjs) call [`subagentPrompt()`](../scripts/subagent-prompt.mjs). It loads the preserved [`subagent-prompts.json`](../references/source-prompts/subagent-prompts.json), selects `Hs` for text or `zs` for structured output, translates only instructions for unavailable tools, appends a permission qualification and the workflow's `Task:` text, and sends the result through the SDK.

| Recovered variant | When Ultracode uses it | Active Autocode counterpart | Exact difference |
| --- | --- | --- | --- |
| `Hs` default text system prompt | Ordinary workflow subagent returning text | Loaded for text calls in both adapters | Source text is retained except the `SendUserMessage` tool-specific line, which now says to return through the final response instead of another channel. A separate permission qualification is appended. |
| `zs` structured system prompt | Agent with `schema` | Loaded for schema calls in both adapters | Five `StructuredOutput` tool-call phrases are translated to SDK structured-result language. The schema-validation correction, end-turn, and no-acknowledgment directions remain. A permission qualification is appended. |
| `Js` custom-agent text suffix | Custom agent type without schema | Preserved, inactive | `agentType` still errors in both adapters; no custom-agent prompt exists to append this suffix to. |
| `Ks` custom-agent structured suffix | Custom agent type with schema | Preserved, inactive | `agentType` still errors; no custom-agent prompt exists to append this suffix to. |
| `jn` shared authority sentence | Included in each of the four variants | Preserved verbatim inside `Hs` and `zs` | Autocode additionally says to follow the usual instruction hierarchy and tool permissions. The recovered sentence's direction to perform the assigned step remains. |

The four recovered variants and shared sentence are preserved **verbatim** in the packaged JSON file. `Hs` and `zs` are executed with the substitutions above; `Js` and `Ks` remain inactive until custom agent types exist. A workflow's own `agent(prompt)` string is supplied at run time, so it has no fixed recovered prose to compare. The four packaged templates contain newly written agent prompts, listed below.

## Why the prose was changed

These are the implementation reasons visible in the code and the design rationale I can substantiate. A reason is **not** proof that the replacement is equivalent. The earlier condensation is recorded here as an error; the current candidate loads the recovered variants.

| Change | Rationale | Was the prose change required? | Parity judgment |
| --- | --- | --- | --- |
| Earlier replacement of `Hs` and `zs` with one shared `SUBAGENT_INSTRUCTIONS` string | I reused one return-to-script instruction for both providers and both output modes. This reduced implementation work. | **No.** The adapters already branch on `opts.schema`. | **Corrected locally:** both adapters now select the recovered text or structured variant. Native-SDK adapter tests check the actual prompt sent. |
| Translate `StructuredOutput` tool-call instructions | The current adapters request structured output through Codex `thread.run(..., {outputSchema})` and Claude `query(..., {outputFormat})`. They do not supply a `StructuredOutput` tool. | **Yes**, the exact tool-call command would be false for this runner. | Current `zs` adaptation retains schema correction, result-only, and end-turn directions with SDK wording. |
| Translate `SendUserMessage` prohibition | The Claude adapter gives agents a limited file-tool list; Codex uses its SDK thread rather than Claude's `SendUserMessage` tool. | **Yes** for that exact tool name in the cross-provider prompt. | Current `Hs` adaptation says to put the answer in the final text response, not another channel. |
| Earlier replacement of `jn` with a permission qualification | A workflow script computes a task string, so the adapter cannot treat that string as new user authority. | The qualification is required; **removing the source's positive direction to perform the assigned step was not**. | **Corrected locally:** `jn` remains verbatim in `Hs` and `zs`; the qualification is appended. |
| Omit `Js` and `Ks` custom-agent suffixes | Both adapters reject `agentType` before creating an agent. There is no custom-agent prompt to append to. | **Yes** for the current implementation. | Functional gap: custom agent types and their suffixes are not implemented. |
| Earlier shortening of the `Edo()` authoring reference into two guides and a skill | I separated API facts from quality patterns and rewrote examples for Autocode's CLI and SDK APIs. | API substitutions were required; **dropping rationale, exact worked prompts, and directive strength was not**. | **Corrected locally:** the complete recovered authoring file is packaged and `SKILL.md` directs the authoring agent to read it, with the Autocode API guide resolving incompatible tool instructions. Installed-skill eval remains necessary to show the agent follows both. |
| Change inline `Workflow` script instructions to a saved script and CLI command | This package exposes `autocode run`, not Claude's built-in `Workflow` tool. The native background task ID, `/workflows` view, and permission dialog are unavailable. | **Yes** for the tool invocation syntax. | The five-case opt-in rule and default pipeline guidance could have been preserved more closely; shortening them was discretionary. |
| Change forced-model guidance to per-call provider/model/effort guidance | Autocode intentionally supports choosing Codex or Claude for each delegated call. It has no forced-subagent-model mode. | **Yes** for unsupported forced-model behavior. | An additional branch would be needed for that source behavior; current guidance cannot be called equivalent. |
| Rewrite keyword and full/sparse/exit reminders | The executable surface is a Codex/Claude plugin hook, and the action is invoking Autocode rather than Claude's `Workflow` tool. | The tool and skill names had to change; **the source's quality and standing-mode directions did not**. | Current reminders are shorter. Installed hosts verified entry/exit state changes; Codex verified keyword injection. Claude keyword, sparse delivery, and equivalent model behavior remain unverified. |
| Use generic prompts in the four runnable templates | I made templates accept user-supplied topics/questions and kept them small. Mixed-provider delegation was added for the cross-agent goal. | **No** for review/research quality prompts. | Generic finder/verifier wording and one-vote review weaken the source examples; no comparative eval justified those reductions. |
| Earlier exclusion of recovered verbatim prompt files from npm | The public package was built as an independent implementation and published without extracted third-party prompt assets. | This was a packaging choice, **not a runtime necessity**. | **Corrected locally:** the eight extracted prompt/prose assets are in the 0.1.1 candidate package. Publication of the revised artifact has not occurred. |

The strongest defensible changes are substitutions for **unavailable tool interfaces**. The earlier condensation of supported instructions was an implementation shortcut and was wrong for the requested maximum reuse. Live Codex text and structured calls have now passed on the candidate; live Claude calls and preserved custom-agent suffixes remain unverified or inactive.

## Worked template prompt differences

| Recovered example/pattern | Packaged Autocode template | Difference |
| --- | --- | --- |
| Canonical review dimensions, structured findings, per-finding skeptical verification, confirmed-only return | [`review-and-verify.js`](../assets/templates/review-and-verify.js) | Takes user-supplied topics instead of source's dimension objects; generic `Review …` finder and `Try to refute …` verifier replace the detailed source prompts. It returns findings passing one verifier, whereas the source's broader quality pattern can use multiple independent votes. |
| Exhaustive review with full-seen deduplication, distinct lenses, dry rounds | [`exhaustive-review.js`](../assets/templates/exhaustive-review.js) | Implements three lenses and two dry rounds with a default four-round cap. Prompt wording is newly written; source's explicit majority/refutation uncertainty wording is weaker in the active prompt. Findings are strings instead of structured file/line/description objects. |
| Multi-modal sweep by file/container, content, entity, time | [`parallel-scout.js`](../assets/templates/parallel-scout.js) and guide example | Template fans out arbitrary questions; it does not encode the four source modes or mandatory independent merge and deep read. The guide describes those steps. |
| Judge panel and loop/count/budget examples | [`quality-patterns.md`](../references/quality-patterns.md) | Guide rewrites these as examples; no dedicated runnable judge template. Budget example uses a soft workflow output-token target instead of source's hard turn-wide shared target. |
| No original mixed-provider template | [`mixed-provider.js`](../assets/templates/mixed-provider.js) | Autocode addition to choose Codex/Claude, model, and effort per task. |

## Consequence

The 0.1.1 candidate now ships the recovered prompt assets and uses `Hs`/`zs` in actual subagent calls with tool-specific substitutions. The skill directs authors to read the full `Edo()` authoring reference. `Js`/`Ks` cannot become active until custom agent types exist. Workflow tool descriptions and reminder strings are preserved but adapted to available interfaces; the original Workflow UI is absent. Entry and exit hooks ran in installed hosts, and Codex keyword injection is verified; Claude keyword and ten-turn sparse delivery still need installed-host tests.
